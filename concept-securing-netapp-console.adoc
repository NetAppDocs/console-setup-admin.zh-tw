= 保護 NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
透過限制 NetApp Console 存取、保護 Console 代理程式以及監控活動以發現未經授權或意外的變更來保護儲存設備操作。

安全性是共享的責任。NetApp 負責保護 Console 服務，而您負責選擇合適的部署模式、控制使用者和服務帳戶存取、保護部署 Console 代理程式的環境，以及監控組織中的活動。



[[choose-the-appropriate-deployment-mode]]
== 選擇合適的部署模式

根據您的連線能力、隔離及操作需求選擇部署模式：

* 標準模式使用雲端託管的 SaaS 應用程式。
* 受限模式將 Console 安裝在公有雲環境中，與 NetApp API 的傳出連線受到限制。
* 私有模式將 Console 安裝在本地或與外界完全隔離的環境中，且不具備連至 NetApp 的傳出連線。


每種模式的功能可用度和安全性要求都不同。link:concept-modes.html["了解NetApp Console部署模式"]。



[[control-identity-and-access]]
== 控制身分和存取

使用身分和存取管理 (IAM) 僅向使用者和服務帳戶授予執行其任務所需的存取：

* 依專案整理資源，並在適當情況下，按資料夾整理資源，以反映您的業務或營運範圍。
* 在組織層級結構的最低層級指派預先定義的角色，以提供所需的存取。
* 定期審查組織成員、服務帳號及其角色。移除不再需要的存取。
* 當身分聯盟符合貴組織的要求時，請使用身分聯盟實作單一登入。身分聯盟在私有模式下無法使用。
* 要求本機使用者使用多因素驗證 （MFA），並將服務帳戶憑證作為機密資訊保護。當服務帳戶憑證遺失或需要輪替時，請重新建立這些憑證。


link:concept-identity-and-access-management.html["在 NetApp Console 中了解 IAM"]。



[[secure-console-agents]]
== 安全 Console 代理程式

Console 代理程式在 Console 與儲存設備系統以及雲端或內部部署環境之間架起橋梁。代理程式會發起與 Console 的通訊；Console 不會發起與代理程式的連線。

對每個代理程式套用下列控制項：

* 將代理程式部署在滿足貴組織主機、網路和存取控制要求的環境中。
* 僅允許必要的傳出網路連線和所需的雲端權限。部署前請審查特定供應商的權限和連接埠要求。
* 當傳出流量必須通過 Proxy 伺服器時，請使用受支援的 Proxy 組態。
* 當使用者透過 HTTPS 存取代理程式 Web 控制台時，請安裝 CA 簽署的憑證。
* 請確保代理程式軟體保持最新狀態。私有模式代理程式必須手動升級。
* 在 AWS 上，請考慮要求主機 Console 代理程式的 EC2 執行個體使用 IMDSv2。


link:concept-agents.html["了解控制台代理"]。



[[reduce-unintended-changes]]
== 減少意外變更

組織管理員可以為組織啟用唯讀模式。唯讀模式有助於防止使用者在請求提升權限之前變更儲存設備系統或使用資料服務。

link:task-enable-read-only-mode.html["了解如何啟用唯讀模式"]。



[[monitor-and-review-activity]]
== 監控及審查活動

使用操作時間軸在 Console 中審查儲存管理和使用者活動。作為組織安全性流程的一部分，定期審查成員存取、角色分配、服務帳戶憑證、代理程式狀態和近期操作。

link:task-monitor-cm-operations.html["了解如何監控 Console 作業"]。
