= 了解NetApp Console代理
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Console 代理程式是一個輕量級軟體元件，您可以將其安裝在網路中，以將儲存基礎架構連接到 NetApp Console。它支援進階儲存協調、資料服務和安全的雲端整合。



== Console 代理程式的作用

Console 代理程式可彌補儲存系統與 NetApp Console 之間的連線差距。它可安全地將您的基礎架構連線至 NetApp API 和 Console、讓您能夠：

* 透過 NetApp Console 發現並監控 AWS、Azure、Google Cloud 和內部部署環境中的儲存系統。
* 在 NetApp Console 上協調儲存系統的儲存資源配置與設定任務。
* 使用智慧型資料保護與管理工作流程。
* 安全地追蹤雲端服務使用情況，並將部署連接到正確的訂閱，以實現準確的計費和成本管理。




=== Console 代理程式架構

代理程式使用輕量級程序運行，這些程序：

* 從 Console SaaS 應用程式拉取或推送資料（標準模式和受限模式）
* 啟動所有通訊 — Console 絕不會主動向代理程式發起撥出通話
* 使用標準管理協定連線至您的儲存系統
* 使用 TLS 1.3 與雲端提供者和 NetApp Console API 進行安全通訊




=== Console 代理程式可用性與作業需求

Console 代理程式對 NetApp Console 至關重要。代理程式必須保持運作和可存取狀態，以確保管理和資料服務不中斷。您有責任確保：

* 代理程式仍在運作中
* 代理程式具有與所需端點的網路連線
* 基礎架構故障能夠迅速解決
* 代理虛擬機器根據 NetApp 相關建議進行維護和升級




== 當您需要 Console 代理時

當您需要執行以下操作時，至少需要部署一個 Console 代理程式：

* 使用受限或私有部署模式（NetApp Console 安裝在您自己的環境中）。可能需要額外的代理才能啟用某些服務。
* 存取進階資料服務（NetApp Backup and Recovery、NetApp Disaster Recovery、NetApp Ransomware Resilience、NetApp Data Classification 等）。
* 管理 Cloud Volumes ONTAP 系統。
* 對內部部署 ONTAP 叢集執行進階管理工作。
* 追蹤授權、監控儲存設備健全狀況並規劃生命週期升級。


如果沒有代理程式，您可以執行基本的儲存探索，並存取有限的監控和儲存管理功能。但是，大多數企業使用案例需要一個或多個操作代理程式。

== Console 代理程式的部署選項

您可以將 Console 代理部署在：

* 亞馬遜網路服務
* 微軟 Azure
* Google雲
+
若要管理 Google Cloud 資源，請將代理程式部署在 Google Cloud 中。內部部署的代理程式無法管理 Google Cloud 資源。

* 在您的場所內（僅限標準或私有模式）


您的 Console 部署模式、儲存環境和資料主權需求決定了代理程式的部署位置。為了實現組織隔離或滿足業務需求，可以在不同環境中部署多個代理程式。

您可以直接從 NetApp Console、雲端市集，或是在 VCenter 或您本地端手動部署代理程式。link:concept-agent-install-options.html["比較部署方法，為您的環境選擇合適的方法"]。



=== NetApp Console SaaS 應用程式（標準模式）的代理程式

在雲端或內部部署代理程式，以橋接與雲端託管 Console SaaS 應用程式的連線。代理程式可啟用進階功能，同時 Console UI 仍可從任何位置存取。

使用 SaaS 應用程式（標準模式）時，您可以直接從 Console 安裝代理程式。您可以將其安裝在 AWS、Azure 或 Google Cloud 上，也可以手動安裝在內部部署環境中您自己的 Linux 主機或 VCenter 環境中。



=== 受限模式下 NetApp Console 的代理程式

在受限模式下，使用者直接透過已安裝的代理程式存取 NetApp Console，而不是透過雲端託管的 SaaS 應用程式存取。您必須至少安裝一個代理程式作為 Console 存取點。啟用資料服務和管理儲存系統還需要其他代理程式。

從雲端供應商的市場安裝代理程式，或手動將軟體安裝到您自己的雲端 Linux 主機、內部部署環境或 VCenter 環境中。



=== 用於私有模式（內部部署或在雲端且無對外連線）的 NetApp Console 代理程式

在私有模式下，使用者可以透過已安裝的代理直接存取 NetApp Console。您必須至少安裝一個代理程式作為 Console 存取點。啟用資料服務和管理儲存系統還需要其他代理程式。

在您的資料中心或實體隔離環境中安裝代理程式。代理程式無法連接到 NetApp API 端點，所有操作均在本地進行，並擁有完全的資料主權和控制權。



=== 必要時使用多個代理程式

每個代理程式獨立運作，可以管理多個儲存系統和資料服務。在需要時部署多個代理程式：

* 依儲存類型或組織功能進行隔離
* 地理或網路區隔需求


例如：

* 在多雲環境中，您可以在 AWS 中部署一個代理程式，在 Azure 中部署另一個代理程式。每個代理程式管理其各自環境中的 Cloud Volumes ONTAP 系統。
* 服務供應商可能會使用一個 Console 組織為客戶提供服務，並使用另一個組織為業務部門提供災難復原服務。每個組織都需要自己的代理程式。




== 控制台代理升級

雲端代理程式在具備出站網際網路存取時會自動升級。對於無法存取網際網路的代理程式（私有模式），請參閱 link:task-upgrade-agent.html["管理控制台代理升級"] 以取得手動升級說明。
