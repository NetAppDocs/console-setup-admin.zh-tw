= 維護 NetApp Console 代理程式 VM
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
藉由將作業系統安全性更新套用至手動安裝的代理程式、回應 CPU、RAM 和磁碟空間警示，以及在需要時調整大小或停止與啟動虛擬機器，來維護 NetApp Console 代理程式虛擬機器

手動安裝 Console 代理程式時，維護代理主機上的作業系統是您（客戶）的責任。例如，您（客戶）應依照公司標準的作業系統分發流程，為代理主機上的作業系統套用安全性更新。

如果代理程式 VM 資源不足或出現效能問題，您應該採取適當措施升級 VM 資源。


NOTE: 如果您在 vCenter 中安裝了代理程式，請使用 Console 維護工具來調整 VM 執行個體的大小link:task-agent-vm-config.html["了解如何在 vCenter 中維護代理程式 VM"^]。



[[apply-operating-system-updates-to-the-manually-installed-agent-hosts]]
== 為手動安裝的代理程式主機套用作業系統更新

無需停止代理主機服務即可套用作業系統安全性修補程式。

為了保持與支援組態的相容性、您應該防止 Docker 或 Podman 在例行作業系統修補期間升級。您可以在更新期間暫時排除 Docker 或 Podman 、或永久設定套件管理程式以跳過 Docker 或 Podman 更新、來執行此作業。

以下範例顯示如何在不同的 Linux 發行版中排除 Docker 或 Podman 更新。請查閱您的 Linux 發行版文件，以取得有關如何排除軟體套件更新的最新說明。

.Podman 範例
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Docker 範例
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resizing-the-vm-or-instance-type]]
== 調整 VM 或執行個體類型的大小

如果您從控制台建立控制台代理，它會使用預設配置在您的雲端提供者中部署 VM 執行個體。建立代理程式後，請勿切換到具有較少 CPU 或 RAM 的較小 VM 執行個體。

如果您收到代理程式虛擬機器資源不足的通知，請考慮升級到具有更多 CPU 或 RAM 的更大虛擬機器執行個體，以確保最佳效能。


NOTE: 如果您在 VCenter 中安裝了代理程式，請使用 Console 維護工具來調整 VM 執行個體的大小。link:task-agent-vm-config.html["了解如何在 VCenter 中調整代理程式虛擬機器的大小"^]。

link:reference-agent-default-config.html["了解代理的預設配置"] 。

如果需要增加代理程式虛擬機器的 CPU 或記憶體，請依照雲端供應商或內部部署虛擬化平台提供的說明調整虛擬機器執行個體的大小。NetApp 建議將目前的 CPU 和記憶體分配增加一倍，以確保最佳效能。下表顯示建議的規模分層，每個分層的 CPU 和記憶體都是前一個分層的兩倍。

[cols="1,1,1"]
|===
| 層級 | CPU（核心或 vCPU） | 記憶體 


| 最低限度 | 8 | 32GB 


| 中 | 16 | 64 GB 


| 大型 | 32 | 128 GB 
|===

== 監控代理

當代理虛擬機器不健康時，控制台會通知您，包括磁碟空間、RAM 和 CPU 問題。在控制台內的通知中心監控這些通知或設定電子郵件通知。磁碟空間、記憶體或 CPU 使用率偶爾增加是正常現象，但如果經常發生，則應採取措施解決。

例如，當代理資源（CPU、RAM 或磁碟空間）連續 30 分鐘超過其總容量的 90% 時，控制台會通知您。之後，如果資源使用率低於該閾值，則通知中心將顯示通知已解決（綠色）。


NOTE: 如果您對修改代理虛擬機器有任何疑問，請聯絡 NetApp 技術支援。

== 連接 Linux VM

如果您需要連線到代理程式運行的 Linux VM，請使用雲端提供者提供的連線選項。

AWS:: 在 AWS 中建立代理執行個體時，請提供 AWS 存取金鑰和金鑰。您可以使用此金鑰對透過 SSH 連線到執行個體。對 EC2 Linux 執行個體使用使用者名稱「ubuntu」。對於 2023 年 5 月之前建立的代理，請使用使用者名稱「ec2-user」。
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["AWS 文件：連接到您的 Linux 實例"^]

--
Azure:: 在 Azure 中建立代理程式 VM 時，您可以指定使用者名稱並選擇使用密碼或 SSH 公鑰進行驗證。使用您選擇的身份驗證方法連線到虛擬機器。
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Azure 文件：透過 SSH 進入您的虛擬機"^]

--
Google雲:: 在 Google Cloud 中建立代理程式時，您無法指定身份驗證方法。但是，您可以使用 Google Cloud Console 或 Google Cloud CLI (gcloud) 連線到 Linux VM 執行個體。
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs：連接 Linux 虛擬機"^]

--
