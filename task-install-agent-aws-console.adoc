= 從 NetApp Console 在 AWS 部署 Console agent
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
無需離開 NetApp Console 即可在 AWS 中部署 Console 代理程式，以便您可以開始管理您的 AWS 資源和資料服務。

在 AWS 中部署 Console 代理程式會在您選擇的 VPC 中啟動一個執行 Linux 和 Console 代理程式軟體的 EC2 執行個體。

.開始之前
* link:concept-agent-install-options.html#agent-console-deploy["瞭解何時從 NetApp Console 部署"]。
* 審查link:reference-limitations.html["控制台代理限制"]。

== 步驟 1：設定連網以在 AWS 中部署 Console 代理程式

請確保您計畫部署 Console 代理程式的網路位置符合下列要求。這些要求可讓 Console 代理程式管理混合雲中的資源和程序。

VPC 和子網:: 建立控制台代理程式時，您需要指定它所在的 VPC 和子網路。


連接到目標網絡:: 控制台代理程式需要與您計劃建立和管理系統的位置建立網路連線。例如，您計劃在本機環境中建立Cloud Volumes ONTAP系統或儲存系統的網路。


出站互聯網訪問:: 部署控制台代理程式的網路位置必須具有出站網路連線才能聯絡特定端點。


從控制台代理聯繫的端點:: 控制台代理需要外部網路存取來聯繫以下端點，以管理公有雲環境中的資源和流程以進行日常操作。
+
--

* IP 位址
* 證書

+
--
建立控制台代理程式後，您需要實作此網路要求。

[[step-2-set-up-aws-permissions-to-deploy-the-console-agent]]

== 步驟 2：設定 AWS 權限以部署 Console 代理程式

根據您選擇的身分驗證方法，僅授予 Console 在您的 VPC 中部署 Console 代理程式所需的 AWS 權限。

選擇以下身分驗證方法之一，並僅設定該方法所需的資訊：

[cols="1a,2a,2a"]
|===
| 方法 | 它的作用 | 您設定的內容 


 a| 
*為我建立角色*
 a| 
主控台會開啟 AWS CloudFormation 快速建立，從而建立主控台所承擔的部署角色。
 a| 
提交堆疊的 AWS 身分的權限。



 a| 
*擔任角色*
 a| 
主控台將擔任您帳戶中現有的 IAM 角色。
 a| 
一項原則和一個 IAM 角色。



 a| 
*AWS 金鑰*
 a| 
控制台使用 AWS 存取金鑰和秘密金鑰。
 a| 
一項原則和一個 IAM 使用者。

|===
使用 *為我建立角色* 和 *承擔角色*，Console 會承擔一個名為 *部署角色* 的 IAM 角色，用於部署 Console 代理程式。部署完成後，Console 代理程式會使用附加到其 EC2 執行個體的分隔 IAM 角色，稱為 *代理程式角色*。預設情況下，Console 會為您建立代理程式角色。link:#aws-agent-role["了解如何使用您自己的代理程式角色"]。



[[set-up-permissions-for-create-role-for-me-cloudformation-quick-create]]
[[aws-permissions-quick-create]]
=== 設定為我建立角色（CloudFormation 快速建立）的權限

使用可以建立 CloudFormation 堆疊和部署角色的 AWS 身分，以便堆疊能夠順利完成而不會出現權限錯誤。

提交 CloudFormation 快速建立堆疊的身份需要系統管理員權限或以下最低權限。這些權限允許 CloudFormation 建立部署角色。這並非代理程式角色的權限。

[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "CloudFormationStack",
      "Effect": "Allow",
      "Action": [
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:GetTemplateSummary",
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:GetRole",
        "iam:PutRolePolicy",
        "iam:DeleteRolePolicy",
        "iam:GetRolePolicy",
        "iam:PassRole",
        "lambda:CreateFunction",
        "lambda:DeleteFunction",
        "lambda:GetFunction",
        "lambda:InvokeFunction"
      ],
      "Resource": "*"
    }
  ]
}
----

如果您選擇 *承擔角色* 或 *AWS 金鑰*，請建立僅包含部署 Console 代理程式所需權限的原則，並將其附加到 Console 使用的角色或使用者。

如果需要，您可以使用 IAM 限制 IAM 策略 `Condition`元素。 https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_condition.html["AWS 文件：條件元素"^]

.步驟
. 前往 AWS IAM 主控台。
. 選擇“策略”>“建立策略”。
. 選擇 *JSON*。
. 複製並貼上以下策略：
+
此原則僅包含從主控台在 AWS 中產品發表主控台代理程式所需的權限link:reference-permissions-aws.html["查看代理程式角色的權限"]。

+

        "iam:PutRolePolicy",
        "iam:CreateInstanceProfile",
        "iam:DeleteRolePolicy",
        "iam:AddRoleToInstanceProfile",

        "ec2:RunInstances",

        "ec2:DescribeSecurityGroups",
        "ec2:RevokeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupIngress",
        "ec2:RevokeSecurityGroupIngress",
        "ec2:CreateNetworkInterface",

        "ec2:DeleteNetworkInterface",

... 選擇您建立的策略。

[[step-3-set-up-your-own-iam-role-for-the-console-agent-optional]]
[[aws-agent-role]]
== 步驟 3：為 Console 代理程式設定您自己的 IAM 角色（選用）

如果您想選擇自訂的代理程式角色，而不是 Console 預設建立的角色，請建立您自己的代理程式角色。請在部署 Console 代理程式之前建立角色。

.步驟
. 登入 AWS 主控台並導覽至 IAM 服務。
. 建立策略：
+
.. 選擇“策略”>“建立策略”。
.. 選擇 *JSON* 並複製並貼上內容link:reference-permissions-aws.html["控制台代理的 IAM 策略"]。
.. 完成剩餘步驟以建立策略。
+
對於標準區域，權限分佈在兩個策略中。由於 AWS 中託管策略的最大字元大小限制，因此需要兩個策略。link:reference-permissions-aws.html["了解有關控制台代理的 IAM 策略的更多信息"] 。



. 建立 IAM 角色：
+
.. 選擇*角色 > 建立角色*。
.. 選擇 *AWS 服務 > EC2*。
.. 透過附加剛剛建立的策略來新增權限。
.. 完成剩餘步驟以建立角色。




.結果
現在，您可以在部署 Console 代理程式時，於 *代理程式部署詳細資料* 中選取代理程式角色。



[[step-4-deploy-the-console-agent]]
== 步驟 4：部署 Console 代理程式

請提供您的驗證、部署、網路和安全性群組詳細資料，以便 Console 在您的 VPC 中啟動 Console 代理程式。

.關於此任務
* 從控制台建立控制台代理程式使用預設配置在 AWS 中部署 EC2 執行個體。建立控制台代理程式後，請勿切換到具有較少 CPU 或較少 RAM 的較小 EC2 執行個體。link:reference-agent-default-config.html["了解控制台代理的預設配置"] 。
* 預設情況下，主控台會建立代理程式角色及其設定檔。如果您提供自己的代理程式角色，請確保在未來的版本中新增權限時更新該角色。link:reference-permissions-aws.html["了解有關控制台代理的 IAM 策略的更多信息"]。


.開始之前
您應該具有以下內容：

* AWS 身分驗證方法：*為我建立角色*、*承擔角色*或 *AWS 金鑰*。
* 滿足組網需求的VPC及子網路。
* EC2 執行個體的金鑰對。
* 如果控制台代理需要代理才能存取互聯網，則提供有關代理伺服器的詳細資訊。
* 已完成 link:#networking-aws-agent["步驟 1"]。
* 已完成 link:#aws-permissions-agent["步驟 2"]。


.步驟
. 選擇“*管理 > 代理*”。
. 在 *Overview* 頁面上，選擇 *Deploy agent > AWS*。
. 在 *代理程式部署的 AWS 憑證* 部分中，選擇下列身分驗證方法之一：
+
** *為我建立角色*：
+
... 選擇您的 AWS 區域並輸入您的 AWS 帳戶 ID。您也可以選擇輸入外部 ID。
... 選擇 *開啟 CloudFormation 快速建立*。
... 在 AWS 中，確認條款並選擇 *建立堆疊*。
... AWS 完成角色建立後，返回主控台並確認角色。


** *承擔角色*：輸入 IAM 角色的 ARN，然後選擇*驗證憑證*。
** *AWS 金鑰*：輸入存取金鑰和秘密金鑰，然後選取*驗證憑證*。


. 在 *代理程式部署詳細資料* 區段中，提供有關 Console 代理程式的詳細資料。
+
** 輸入名稱。
** 新增自訂標籤（元資料）。
** 選擇您要讓 Console 建立代理程式角色，還是選擇您link:#aws-agent-role["自行設定"]的代理程式角色。
** 選擇是否要加密控制台代理的 EBS 磁碟。您可以選擇使用預設加密金鑰或使用自訂金鑰。


. 在 *連網組態* 部分，為 Console 代理程式指定 VPC、子網路和金鑰對，選擇是否啟用公用 IP 位址，並可選擇指定 Proxy 組態。
+
確保您擁有正確的金鑰對來存取控制台代理虛擬機器。如果沒有密鑰對，您就無法存取它。

. 在 *安全性群組* 區段中，選擇要建立新的安全性群組，還是選取允許所需傳入和傳出規則的現有安全性群組。
+
link:reference-ports-aws.html["查看 AWS 的安全群組規則"] 。



. 檢閱您的選擇，以確認您的設定是否正確。
+
.. 預設情況下會選取 *Validate agent configuration* 核取方塊，以便 NetApp Console 在部署時驗證網路連線需求。如果 NetApp Console 無法部署代理程式，它會提供報告以協助您進行疑難排解。如果部署成功，則不會提供報告。


+
[NOTE]
====
** 如果您仍在使用用於代理升級的link:reference-networking-saas-console-previous.html["先前的端點"]，驗證將失敗並顯示錯誤。為避免這種情況，請清除核取方塊以跳過驗證檢查。
** 在安裝期間、NetApp 會檢查代理主機至少有 80% 的可用磁碟空間總計、其中包括 48 GB 在 `/opt`和 32 GB 在 `/var`（總計 80 GB）。安裝後、需要至少 20% 的磁碟總計保持可用、其中包括 12 GB 在 `/opt`和 8 GB 在 `/var`（總計 20 GB）。


====
. 選擇“*新增*”。
+
Console 會在大約 10 分鐘內部署 Console 代理程式。請停留在該頁面上，直到程序完成。



.結果
過程完成後，即可從控制台使用控制台代理。

如果您在建立控制台代理程式的相同 AWS 帳戶中擁有 Amazon S3 儲存桶，您將看到 Amazon S3 工作環境自動出現在 *系統* 頁面上。 https://docs.netapp.com/us-en/storage-management-s3-storage/index.html["了解如何從NetApp Console管理 S3 儲存桶"^]



[[troubleshoot-a-failed-console-agent-deployment]]
[[troubleshoot-agent-deployment]]
== 疑難排解 Console 代理程式部署失敗的問題

使用部署報告尋找阻止 Console 代理程式部署的原因，然後重試。

只有在選取 *驗證代理程式組態* 核取方塊時，Console 才會提供報告。如果部署成功，則沒有報告。

.步驟
. 在 *代理程式部署失敗* 對話方塊中，選擇 *下載報告*。
+
主控台下載包含驗證報告的 PDF 檔案。

. 請審閱報告並解決報告中列出的問題。
. 在對話方塊中，選擇 *重新開始*，然後再次完成部署。
