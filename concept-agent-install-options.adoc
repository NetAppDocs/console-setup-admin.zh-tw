= 選擇 Console 代理程式部署方法
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
使用 NetApp Console、雲端供應商的市場或在 Linux 主機上手動安裝軟體來部署 Console 代理程式。您的部署方法決定了您對主機的控制權以及啟動速度。

對於雲端部署、您可以在 Amazon Web Services （AWS）、Microsoft Azure 或 Google Cloud 中部署代理程式。



== 從 NetApp Console 部署

NetApp 建議在使用標準模式時，從 NetApp Console 進行部署。NetApp Console 會引導您完成網路和權限設定，然後自動在您的雲端供應商中啟動 VM 或執行個體。Console 會引導您完成網路和權限設定，然後自動在您的雲端供應商中啟動 VM 或執行個體。

在以下情況下選擇此方法：

* 您正在具有傳出網際網路存取的標準雲端環境中進行部署。
* 您希望以最少的手動設定，以最快的速度讓代理程式運作起來。


[cols="47,47"]
|===
| 優勢 | 缺點 


 a| 
* 引導式設定 — NetApp Console 可在單一工作流程中處理 VM 建立、軟體安裝和初始註冊
* 自動套用正確的 VM 映像和組態
* 任何雲端部署方法中手動步驟最少

 a| 
* 不適用於內部部署、受限模式或實體隔離環境


|===

== 從雲端供應商市場部署

從 AWS Marketplace 或 Azure Marketplace 進行部署時，代理程式的安裝將直接從市場啟動，而不是從 NetApp Console 啟動。


NOTE: Google Cloud 提供了一個與市場功能類似的選項，可以使用 Google Cloud 工具（gcloud CLI 或 Google Cloud Console）而不是傳統的市場清單。

在以下情況下選擇此方法：

* 貴組織要求所有雲端軟體都必須透過市場管道採購。
* 您更傾向於透過雲端服務提供者的介面而不是 NetApp Console 來發起部署。


[cols="47,47"]
|===
| 優勢 | 缺點 


 a| 
* 對於已經在雲端供應商主控台中工作的團隊而言，熟悉的部署介面

 a| 
* 部署是在 NetApp Console 之外啟動，因此無法使用引導式工作流程


|===
link:task-install-agent-aws-marketplace.html["從 AWS Marketplace 部署 Console 代理程式"] link:task-install-agent-azure-marketplace.html["從 Azure 應用程式商店部署 Console 代理程式"] link:task-install-agent-google-gcloud.html["使用 Google Cloud 工具在 Google Cloud 中部署 Console 代理程式"]



== 在雲端的 Linux 主機上手動安裝

手動安裝可讓您將 Console 代理軟體直接安裝在您提供和管理的 Linux 主機上，該主機可以位於 AWS、Azure、Google Cloud 或內部部署環境。

在以下情況下選擇此方法：

* 您需要在受限模式或私有模式環境中部署,而不需要傳出網際網路存取。
* 貴組織要求所有軟體都必須安裝在預先核准的內部管理主機上。


[cols="47,47"]
|===
| 優勢 | 缺點 


 a| 
* 支援輸出網際網路存取受限的環境（受限模式或私有模式）
* 當 Console 代理程式可以存取網際網路時，升級將自動處理。

 a| 
* 大多數部署方法的步驟。您必須準備主機、安裝 Podman 或 Docker、設定網路、安裝軟體並手動提供權限
* * 部署是在 NetApp Console 之外啟動，因此無法使用引導式工作流程


|===
link:task-install-agent-aws-manual.html["在 AWS 中手動安裝 Console 代理程式"] link:task-install-agent-azure-manual.html["在 Azure 中手動安裝 Console 代理程式"] link:task-install-agent-google-manual.html["在 Google Cloud 手動安裝 Console 代理程式"]



== 使用 vCenter（OVA）手動在內部部署安裝

如果您使用 VMware vCenter，可以透過匯入 OVA（開放式虛擬設備）檔案來部署 Console 代理程式。OVA 是預先配置的 VM 映像，您可以使用 vSphere 用戶端進行部署，無需安裝 Linux 或配置容器執行階段。

在以下情況下選擇此方法：

* 您正在 VMware 環境中進行內部部署。
* 您想要更簡單的內部部署安裝、需要較少的維護和 Linux 設定。



NOTE: 您無法透過內部部署 Console 代理程式管理 Google Cloud 資源。若要管理 Google Cloud 資源，請在 Google Cloud 中安裝代理程式。

[cols="47,47"]
|===
| 優勢 | 缺點 


 a| 
* 更簡單的內部部署安裝，無需 Linux 或容器執行階段設定
* 僅限內部部署;不適用於雲端部署
* 包含功能表導向的維護主控台，用於執行代理程式維護工作
* VMware 管理員熟悉的部署工作流程
* * 預先設定的 VM 映像有助於防止錯誤，並簡化維護工作

 a| 
* 需要 VCenter；無法直接安裝在裸 ESXi 主機上


|===
link:task-install-agent-on-prem-ova.html["使用 vCenter 進行內部部署"]



== 手動安裝內部部署（不使用 vCenter）

您可以手動將 Console 代理程式安裝到任何內部部署 Linux 主機上。您必須先設定 Linux 主機和容器執行時間環境（Docker 或 Podman），然後再安裝 Console 代理程式。

在以下情況下選擇此方法：

* 您是在內部部署，沒有 VMware vCenter 環境。
* 您熟悉 Linux 管理，並且希望自行管理底層主機。
* 您希望控制 Console 代理程式何時升級。


[cols="47,47"]
|===
| 優勢 | 缺點 


 a| 
* 可在任何相容 Linux 的內部部署硬體或 VM 平台上運作—無需 VMware
* 支援私有模式（實體隔離）部署，無需對外網際網路存取

 a| 
* 您需要瞭解如何使用 Linux 並自行設定 Docker 或 Podman
* 當發布新版本時，您負責手動將升級套用至 Console 代理程式


|===
